Task first, verb second.

Worked flows for the things you actually do. Steps marked [owner] need the owner (a terminal on stdin, or SEC_OWNER=1) — an agent hands them over as an exact command. Unsure which verb moves secrets? sec help move.

Call an API with a key

sec ls --json                                   # is the name there?
sec exec -- curl -sS https://api.x.com -H "Authorization: Bearer {{STRIPE_KEY}}"
# output comes back with [REDACTED:STRIPE_KEY] — that is normal

Not in the vault? [owner] sec set STRIPE_KEY --source <url> --place. An agent never fetches it itself.

A tool wants env vars

sec run STRIPE_KEY,DB_URL=DATABASE_URL -- go test ./...

Values exist only in the child's environment; output is scrubbed.

Set up a repo's .env

sec env list                                    # re-scans: environment → file → key count
sec import .env.production --project reqsume --env production   # owner has a real file
sec render .env.template --out .env             # write it from the vault…
sec env write .env DB_PW=DATABASE_PASSWORD      # …or key by key
sec keys                                        # exit 1 lists keys the project still lacks

Ask which environment if it is unclear; never reuse an old path.

Someone pasted a secret in chat

sec set NAME <<'EOF'
…
EOF
sec rotate NAME                                 # recommended: the value transited chat

From then on use {{NAME}}. Never repeat the value.

A new password or token

sec gen --save DB_PW --env .env=DB_PASSWORD
sec gen --save SESSION_KEY --hex --len 32

Never invent one yourself; never print it.

A daemon with no TTY needs a value in a file

sec get NAME --out /run/app/pgpass             # NEW 0600 file; refuses existing file or symlink

Audited. For a whole config use sec render.

A certs folder onto a server

sec file add ./certs TLS                        # or: sec file add ./sa.json  → SA_JSON
sec push SA_JSON ./app/sa.json                  # locally, where the program reads it
sec push TLS ssh://web/etc/app/certs            # on a server
sec push TLS ssh://web+docker://api/run/certs   # inside a container on that server
sec where TLS                                   # every place it lives

[owner] the first push to another machine. After that sec rotate and sec ok keep every copy current.

Secrets into a k8s pod, via ssh

sec sync --dry DB_PW,API_KEY ssh://bastion+k8s://prod/api-7d9f   # names + remote key fingerprint, nothing sent
sec sync DB_PW,API_KEY ssh://bastion+k8s://prod/api-7d9f
sec sync DB_PW k8s://[context/]ns/pod[/container]            # direct, when kubectl reaches it

[owner] first contact pins the remote key (or sec target add web-key age1… once). "sec not found" → [owner] sec sync … --install. "REMOTE KEY CHANGED" → stop and tell the owner; never --repin yourself. Also docker://, podman://, jump hosts ssh://bastion+ssh://db.

Put or upgrade sec on a remote box

sec remote status ssh://db                      # its version vs this one, vault y/n
sec remote upgrade ssh://db                     # keeps sec.prev, rolls back on failure
sec remote uninstall ssh://db                   # keeps its vault

[owner] install / upgrade / uninstall; --purge only at a real terminal. No secrets move.

A new machine with no connection

sec id                                          # there → age1…
sec export --only A,B --for age1… --out x.sec   # here  [owner]
sec import x.sec                                # there

[owner] sec export. Works over email, USB, air gap.

CI or e2e with a read-only vault

SEC_READONLY=1 sec run DB_PW -- ./e2e.sh

Only ls run exec render seal keys where logs audit env id use project work. Anything else is refused — report it; do not look for a way around.

A key leaked

sec where NAME                                  # where it lives
sec audit --name NAME --since 7d                # who used it
sec rotate NAME --gen --hook ./alter-user.sh    # or owner pastes the new one: sec rotate NAME
sec audit --retired                             # old versions still to revoke at the provider

Then sec rotate NAME --purge once revoked upstream.

Is everything in sync / healthy

sec ok --dry                                    # report only
sec ok                                          # re-push stale copies, list missing keys + old versions

Before committing or sharing a file

sec seal FILE --check                           # exit 1 = a real value is in it
sec seal FILE                                   # put {{NAME}} back

Work in one project and environment

sec use reqsume --env dev                       # show: sec use · clear: sec use --unset
sec exec -- psql "{{reqsume@production:DB_URL}}"   # or inline, per value

Or per command --project P --env E.

A GitHub or GCP secret

sec place NAME --gh owner/repo[:env]
sec place NAME --gcp my-project

Never gh secret set by hand; the placement is recorded so rotate re-pushes it.

Windows

curl.exe -fsSL https://raw.githubusercontent.com/muthuishere/sec/main/install.cmd -o "%TEMP%\sec-install.cmd" && "%TEMP%\sec-install.cmd"
sec init
sec sync DB_PW ssh://winbox --install           # [owner] detects PowerShell on the far end

Same verbs on Windows; --install streams the right build, no admin needed.

Which verb moves secrets? Another sec you can reach → sec sync. A program that reads a file / .env / folder → sec push. No connection → sec export --for + sec import. sec itself → sec remote. Full flags: docs.
